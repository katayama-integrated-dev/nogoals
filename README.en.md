# NoGoals

[日本語](README.md)

NoGoals is a static site generator written in Lean 4 that builds bilingual Japanese and English websites and proves or checks, on every build, what it claims about them.

The name comes from Lean's `No goals` message, the state a proof ends in when nothing is left to prove. A NoGoals build is meant to end the same way: every obligation about the site discharged before anything is published.

Built by Katayama Mathematical Sciences, a division of [Katayama Integrated Development](https://www.katayama.dev/).

Site: https://nogoals.org · [![ci](https://github.com/katayama-integrated-dev/nogoals/actions/workflows/ci.yml/badge.svg)](https://github.com/katayama-integrated-dev/nogoals/actions/workflows/ci.yml)

## What it does

- **Links resolve.** An internal link is an index into the site's pages; a theorem proves every rendered link resolves.
- **Assets are declared.** An asset reference names a declared asset of the right kind, which the type checker enforces; `--audit` checks the files on disk.
- **Both languages are present.** Every text field carries a Japanese and an English value; a page missing either does not compile. Translation quality is not checked.
- **One route set.** Canonical links, hreflang alternates, the sitemap and the feeds are all generated from the same routes.
- **Checks on the emitted bytes, fail-closed.** Under `--audit`, CSP, HTML validity, SEO and permalink permanence are checked on the files the build writes. A failing check quarantines the build in `build.failed/` and leaves the last green `build/` untouched.
- **A receipt.** Every build writes a machine-readable receipt to `verification/receipt.json` in its output; a deploy script can refuse to publish without a passing one.

This version targets Cloudflare Pages' serving rules (`_headers`, `_redirects`).

## Quick start

A site is a Lean package next to a NoGoals checkout named `nogoals`. You need
[elan](https://github.com/leanprover/elan) (it installs the pinned Lean
toolchain) and Node.js 22.22+ or 24.8+.

```bash
git clone https://github.com/katayama-integrated-dev/nogoals nogoals
cp -R nogoals/skills/nogoals/assets my-site
cd my-site && npm ci
./scripts/build.sh --audit --update-baseline   # first build: records the permalink baseline
./scripts/build.sh --audit                     # every build after that
```

The first build fetches Mathlib and takes a while. The scaffold audits green
as copied. [`skills/nogoals/SKILL.md`](skills/nogoals/SKILL.md) explains the
model and walks through adding pages and articles, reading a red build, and
deploying; an agent can follow it directly.

## Building NoGoals itself

```bash
lake build                                      # the proofs check during the build
lake script run test                            # #guard suite, axiom audit, process-boundary tests
./verify.sh                                     # recompute the counts; nonzero exit on drift
cd site && npm ci && ./scripts/build.sh --audit # NoGoals's own site, every gate
```

The toolchain is pinned: Lean 4.28.0 in `lean-toolchain`, Mathlib by commit in
`lakefile.lean` and `lake-manifest.json`. Do not run `lake update`.

## Design

NoGoals has a verified kernel (IR, refine, plan, render) that vouches for
structure: links, assets, output paths, both languages, escaping. A declared
trusted shell, the site's presentational vocabulary, fills typed slots in
that kernel; nothing rewrites the emitted HTML afterwards. Every guarantee
states its enforcement tier: type-enforced (the invalid state cannot be
constructed), theorem-proved (proved in Lean's kernel over arbitrary sites),
or runtime-gated (checked at build time, fail-closed). NoGoals grew out of
Omega, an earlier internal effort to coordinate many parallel agents writing
formally verifiable components; what held up was a narrower verification
surface for one class of artifact, a website.
[`DESIGN.md`](DESIGN.md) holds the principles and the publish gates,
[`ARCHITECTURE.md`](ARCHITECTURE.md) the kernel and shell, and
[`skills/nogoals/SKILL.md`](skills/nogoals/SKILL.md) the site author's view.

## Architecture

```
NoGoals/
├── DSL.lean       # User-facing site definition (typed, bilingual L content)
├── Compile.lean   # DSL front door: checks, chrome, verification report
├── Compile/       # Guarantee evidence; report and receipt renderers
├── Bridge.lean    # A site's data to its verified SiteV and site-specific guarantees
├── Build.lean     # NoGoals.Build.run: a SiteBuild spec to an audited artifact
├── Meta.lean      # Typed sitemap / robots / _headers / manifest (+ theorems)
├── IR/            # The verified core: Atoms, Assets, Route, HtmlRaw, HtmlVerified
├── Resolve/       # refine : raw → verified (errors fatal and located)
├── Render/        # Typed HTML tree, escaping, feeds, build plan (unique_paths, coverage)
├── Verify/        # Build-time gates: strings, dates, attestations, HTML facts,
│                  #   html-validate, permalinks, external links, site audit
├── CLI/           # The nogoals executable
├── Images/        # Srcset mathematics (proof showcase)
├── Nav/           # BFS reachability soundness (proof showcase)
└── Test/          # #guard suite + the kernel-level axiom audit
```
