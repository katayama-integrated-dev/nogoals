# NoGoals — overview

*A static site generator where broken websites are impossible.* NoGoals uses
Lean 4's dependent type system to make invalid site states unrepresentable;
[What it does](README.en.md#what-it-does) in the English README lists each guarantee and
how it is enforced.

**Who it's for.** Three audiences, ranked: (1) the publisher of katayama.dev,
the first consumer, whose maintenance edits the gate suite protects and whose
needs motivate every feature; (2) anyone building a static site with NoGoals
— the tool is open source, and the way in is the agent skill in
`skills/nogoals/` (an agent scaffolds and maintains a site against the one
Lean API); (3) the reader of a published artifact, who discovers a website
whose correctness claims are machine-checked and can verify them in under a
minute.

**Current state (September 25, 2026).** v0.1.0 is the first public release.
Toolchain: Lean v4.28.0, Mathlib v4.28.0, both pinned. The kernel has one
route model (validated segments, closed `Lang`, one path function,
browser-semantics `resolveUrl` with a closure theorem), typed anchors, and a
typed-tree renderer whose grammar theorem includes void/normal tag classes.
Every page of katayama.dev is one typed tree with a single named `raw` slot;
runtime gates read facts from a pinned browser-grade parser; permalinks are
URL obligations with redirects rendered from the typed map; the deploy
script refuses anything but a full-audit receipt of the checked-out
commits. nogoals.org is built from `site/` and served from Cloudflare,
published by its audited deploy script; CI runs `./verify.sh` on every push
and pull request. Not done yet: the proof-showcase nits (BFS dedup, srcset
uniqueness) and srcset production wiring.
