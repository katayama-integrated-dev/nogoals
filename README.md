# NoGoals

[English](README.en.md)

NoGoals は Lean 4 で書かれた静的サイトジェネレーターである。日本語と英語の二言語サイトを生成し、サイトについて掲げる保証をビルドのたびに証明または検査によって確かめる。

名前の由来は、証明が完了してゴールが残っていないことを示す Lean のメッセージ `No goals` である。NoGoals のビルドも、公開前にサイトに必要な証明とチェックをすべて終えた状態で終えることを目指す。

NoGoals は、[片山総合開発](https://www.katayama.dev/)の片山数理事業本部が開発する。

ウェブサイト: https://nogoals.org · [![ci](https://github.com/katayama-integrated-dev/nogoals/actions/workflows/ci.yml/badge.svg)](https://github.com/katayama-integrated-dev/nogoals/actions/workflows/ci.yml)

## What it does

- **リンクを解決できる。** 内部リンクはサイト内のページへの添字として表す。そこから生成するすべてのリンクが解決できることを定理で証明する。
- **アセットは宣言に基づいて参照する。** アセット参照は、宣言済みのアセットのうち種類が一致するものを指す。この制約は型検査器が保証し、`--audit` ではディスク上のファイルを検査する。
- **両言語の値を必須とする。** 各テキストフィールドは日本語と英語の値を持ち、どちらかを欠くページはコンパイルが通らない。翻訳の品質は検査しない。
- **ルート集合を共通化する。** canonical リンク、hreflang による言語別リンク、サイトマップ、フィードをすべて同じルート集合から生成する。
- **出力ファイルを検査し、失敗時はビルドを通さない。** `--audit` では、ビルドが書き出すファイルを対象に CSP、HTML の妥当性、SEO、パーマリンクの永続性を検査する。検査に失敗したビルドは `build.failed/` に隔離し、直近で検査に通った `build/` はそのまま保持する。
- **検証記録を残す。** ビルドごとに、機械可読な検証記録を出力先の `verification/receipt.json` に書き出す。デプロイスクリプトは、合格を示す記録がなければ公開を拒否できる。

このバージョンは Cloudflare Pages の配信ルール（`_headers`、`_redirects`）を対象とする。

## Quick start

サイトは、`nogoals` という名前の NoGoals チェックアウトと同じ親ディレクトリに置く Lean パッケージとして構成する。必要なのは [elan](https://github.com/leanprover/elan)（固定された Lean ツールチェーンをインストールする）と Node.js 22.22+ または 24.8+ である。

```bash
git clone https://github.com/katayama-integrated-dev/nogoals nogoals
cp -R nogoals/skills/nogoals/assets my-site
cd my-site && npm ci
./scripts/build.sh --audit --update-baseline   # first build: records the permalink baseline
./scripts/build.sh --audit                     # every build after that
```

初回ビルドでは Mathlib を取得するため、時間がかかる。ひな形はコピーした状態のまま監査に通る。[`skills/nogoals/SKILL.md`](skills/nogoals/SKILL.md) は、サイトのモデル、ページや記事の追加、ビルド失敗時の出力の読み方、デプロイの手順を解説する。エージェントもこの手順をそのまま利用できる。

## Building NoGoals itself

```bash
lake build                                      # the proofs check during the build
lake script run test                            # #guard suite, axiom audit, process-boundary tests
./verify.sh                                     # recompute the counts; nonzero exit on drift
cd site && npm ci && ./scripts/build.sh --audit # NoGoals's own site, every gate
```

ツールチェーンのバージョンは固定されている。Lean 4.28.0 は `lean-toolchain` で、Mathlib は `lakefile.lean` と `lake-manifest.json` のコミット指定で固定する。`lake update` は実行しない。

## Design

NoGoals の検証済みカーネル（IR, refine, plan, render）は、リンク、アセット、出力パス、両言語の存在、エスケープといった構造上の性質を保証する。サイトの表示に使う部品を定義するシェルは、信頼対象として明示し、カーネルの型で制約されたスロットを埋める。出力後の HTML を書き換える処理はない。各保証には、型による保証（type-enforced：不正な状態を構築できない）、定理による保証（theorem-proved：任意のサイトについて Lean のカーネルで証明する）、実行時の検査（runtime-gated：ビルド時に検査し、失敗時はビルドを通さない）のいずれによるものかを明示する。

NoGoals の原点は、形式検証可能なコンポーネントを多数のエージェントで並列に開発するための、先行する社内プロジェクト Omega にある。その経験を踏まえ、NoGoals は成果物をウェブサイトに絞り、検証対象を限定する設計を採る。

[`DESIGN.md`](DESIGN.md) に設計原則と公開時のゲート、[`ARCHITECTURE.md`](ARCHITECTURE.md) にカーネルとシェルの構成、[`skills/nogoals/SKILL.md`](skills/nogoals/SKILL.md) にサイト作成者向けの説明をまとめる。

## Architecture

```
NoGoals/
├── DSL.lean       # User-facing site definition (typed, bilingual L content)
├── Compile.lean   # DSL front door: checks, chrome, verification report
├── Compile/       # Guarantee evidence; report and receipt renderers
├── Bridge.lean    # A site's data to its verified SiteV and site-specific guarantees
├── Build.lean     # NoGoals.Build.run: a SiteBuild spec to an audited artifact
├── Meta.lean      # Typed sitemap / robots / _headers / manifest (+ theorems)
├── IR/            # The verified core: Atoms, Assets, Route, HtmlRaw, HtmlVerified
├── Resolve/       # refine : raw → verified (errors fatal and located)
├── Render/        # Typed HTML tree, escaping, feeds, build plan (unique_paths, coverage)
├── Verify/        # Build-time gates: strings, dates, attestations, HTML facts,
│                  #   html-validate, permalinks, external links, site audit
├── CLI/           # The nogoals executable
├── Images/        # Srcset mathematics (proof showcase)
├── Nav/           # BFS reachability soundness (proof showcase)
└── Test/          # #guard suite + the kernel-level axiom audit
```
